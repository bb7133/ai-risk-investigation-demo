# Risk Demo AI Agent Configuration

Use this skill when the user asks how the demo agents become "real AI agents", how to use Codex or another local agent CLI, or why the UI fell back to deterministic output.

## Runtime Model

The backend has four investigation lanes:

- `customer`: customer profile, baseline, and memory review
- `merchant`: merchant profile and merchant memory review
- `network`: graph and evidence expansion
- `policy`: policy matching and action recommendation

Both the initial case timeline and the bottom chatbox use the same runtime path:

1. Load the current case bundle from TiDB.
2. Build scoped tool observations for one agent lane.
3. Send the task, role, and observations to the configured provider.
4. Require strict JSON output with `narrative`, `finding`, and `confidence`.
5. Fall back to deterministic local skills if the provider is unavailable or times out.

## Codex CLI Provider

Codex CLI is the current local real-agent provider.

Create or update `/Users/bb7133/.ai-risk-demo.env`:

```bash
export RISK_AGENT_PROVIDER=codex
export RISK_CODEX_BIN=/opt/homebrew/bin/codex
export RISK_AGENT_TIMEOUT_MS=60000
# Optional:
# export RISK_CODEX_MODEL=<model>
```

Restart the API:

```bash
launchctl kickstart -k gui/$(id -u)/local.ai-risk-demo.api
```

Validate:

```bash
curl -sS http://127.0.0.1:8787/api/health
curl --max-time 180 -sS http://127.0.0.1:8787/api/cases/RC00000697/timeline
curl --max-time 180 -sS http://127.0.0.1:3000/api/cases/RC00000697/events
```

Expected signs:

- `/api/health` reports `agentRuntime: "codex-cli"`.
- Timeline and events include `Real AI agent response generated by Codex CLI`.
- First timeline load is slower than deterministic mode because all four lanes call Codex.

## OpenAI-Compatible Provider

Use only when a real API key is available in the service environment:

```bash
export RISK_AGENT_PROVIDER=openai
export OPENAI_API_KEY=<redacted>
export RISK_AGENT_MODEL=gpt-4.1-mini
export RISK_AGENT_TIMEOUT_MS=25000
```

Do not print, commit, or paste API keys into chat.

## Claude Code Or Other Local CLI Providers

The current code has a built-in Codex CLI adapter and an OpenAI-compatible adapter. To use Claude Code as a provider, add a local CLI adapter in `server/index.mjs` that follows the same contract as `runCodexAgent()`:

- accept the same `agentTaskContext`
- run the CLI with a read-only project sandbox where possible
- pass the prompt through stdin or an equivalent safe channel
- capture only the final assistant message
- parse strict JSON: `{ "narrative": "...", "finding": "...", "confidence": 0.0 }`
- expose explicit env vars, for example `RISK_AGENT_PROVIDER=claude-code`, `RISK_CLAUDE_BIN`, and `RISK_AGENT_TIMEOUT_MS`
- keep deterministic fallback behavior

Local Claude Code command shape to validate before wiring it into the server:

```bash
claude --print \
  --output-format json \
  --no-session-persistence \
  --permission-mode default \
  --tools "" \
  --model sonnet \
  "$PROMPT"
```

The adapter should extract the final assistant text from Claude's JSON result, parse the strict response JSON inside it, and return the same internal response object used by the Codex adapter.

Do not document Claude Code as active until `/api/health` can report it and timeline/chat calls verify real Claude-generated responses.

## Troubleshooting

- If `/api/health` reports `deterministic-fallback`, the selected provider is missing, not configured, timed out, or failed.
- If case opening is slow but works, that is expected for real local agents; timeline invokes four lanes.
- If chat works but timeline does not, check `buildAgentTimeline()` and `/api/cases/:id/timeline`.
- If timeline works but the UI does not update, check the Next adapter `/api/cases/:id/events`.
- Check logs:

  ```bash
  tail -100 /tmp/ai-risk-demo-logs/api.err.log
  tail -100 /tmp/ai-risk-demo-logs/frontend-next.err.log
  ```
